# Reflection: Assignment 15 — Cross-Project Contributions

## Introduction
Assignment 15 required me to contribute to peers' repositories by submitting pull requests. I contributed to three different projects: UniMatch University Application System, SmartBin Campus Rewards, and Student Early Warning System.

## Contributions Made
I focused on documentation improvements across all three projects. For UniMatch, I added request and response examples to the OpenAPI YAML file which makes the API documentation more useful for developers. For SmartBin, I added docstrings to all 17 API endpoint functions in main.py which improves code readability. For the Student Early Warning System, I improved the CONTRIBUTING.md by adding a Table of Contents and a Troubleshooting section.

## Challenges in Contributing to Other Projects
The biggest challenge was understanding each project's structure quickly enough to make a meaningful contribution. Every project has its own conventions, folder structure, and coding style. Before making any changes I had to read through the code carefully to understand what was already there and what was missing.

Another challenge was choosing the right issue to work on. I wanted to pick something that was genuinely useful but also achievable in a short time. Documentation issues turned out to be perfect for this — they add real value without risking breaking any existing functionality.

The branch protection rules on some repos meant my PRs could not be merged without a review from the repo owner, which is out of my control. Two of my three PRs were merged quickly which shows the changes were useful and well received.

## Lessons Learned
Working on other people's codebases taught me to read code carefully before touching it. I learned to respect the existing conventions and not impose my own style. I also learned that a small focused PR is much more likely to get merged than a large complex one.

The open-source workflow of fork, branch, PR is now very natural to me after doing it across three different repositories. I also learned the importance of writing a clear PR description that explains what was changed and why — both Mabotse and Thandeka merged my PRs quickly which I think was partly because the descriptions were clear and the changes were easy to review.

## Conclusion
Contributing to peers' repositories was a valuable experience that mirrors real-world open-source collaboration. The skills I practiced — forking, branching, submitting PRs, writing clear descriptions, and responding to the review process — are directly applicable to professional software development.
